## P3-01 的性能与功能验收方法

- 选英日首页、提示指南、角色页、搜索和材料表作为代表页面，记录测试设备、网络/CPU 限速、工具版本与日期；固定条件重复 3 次，报告中位数与异常项。
- 实验室目标：移动 Lighthouse Performance ≥ 90、LCP ≤ 2.5 秒、CLS ≤ 0.1；键盘/可访问性检查结合实际操作，不能只以自动评分通过代替。
- 搜索、菜单、提示和工具在生产 CSP 下工作；图片按显示尺寸选择响应式资源，说明图延迟加载且预留固有尺寸，避免布局跳动。
- INP 的真实用户目标为 ≤ 200ms，待有足够现场数据后观察；当前没有现场指标，实验室交互测量单独标注，不能声称 Core Web Vitals 已通过。
- 完成必要修复后运行项目检查，通过 GitHub 触发 Pages 发布，再对生产页面复核。此任务不以本次配图的窄屏检查作为完整质量审查。

## 发布门槛与阶段完成标准

每项代码或内容变更完成 `npm run check && npm test && npm run build`，通过 GitHub 提交检查和 Pages 自动生产部署，再运行 `npm run verify:deployment -- https://silverpalaceguide.com`。改动涉及的页面另外做浏览器检查；未变化的功能不重复扩大测试范围。

本阶段完成意味着：质量阻断问题已处理，至少 **1 篇真实案件、1 条实测路线、1 个完整材料区间** 可以公开使用，核心内容有对应日语版本，来源/版本/核验日期清楚，三个特色形成可复查的完整体验。没有实测资料时，只能报告相应开发或采集工作的完成状态。

账号、跨设备同步、互动地图、第三语言和批量角色排行留待首组内容及维护流程稳定后评估。统计如需增加客户端脚本或事件采集，另行明确用途并同步隐私说明；用户的个人笔记、库存与备份不作为分析内容。
