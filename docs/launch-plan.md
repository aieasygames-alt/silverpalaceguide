# Silver Palace Guide 第一版筹备与上线方案

制定日期：2026-11-21（Asia/Shanghai）
状态：筹备基线，供后续设计、开发和内容制作使用。

## 1. 定位与成功标准

Silver Palace Guide 是面向国际服玩家的非官方攻略站，以英语为主，同步建设日语核心内容，通过案件分级提示、探索攻略和养成工具解决具体游玩问题。

品牌表达：**Silver Palace Guide — Case Hints, Exploration & Build Planning.**

用户首次进入站点，应能快速完成以下任一任务：

1. 根据案件名称和当前卡点，先取得不直接揭晓答案的提示，必要时再展开证据与完整解法。
2. 根据地点、任务或解谜目标，找到前置条件、路线与结果确认方法。
3. 输入养成目标和已有材料，得到缺口与可勾选的准备清单。

首版不追求资料条目总量。成功首先意味着攻略可靠、入口明确、语言准确、版本可辨，以及工具结果可解释。

## 2. 受众与语言决策

### 2.1 已有证据与限制

- 2026-10-31 发行新闻稿称全球预约超过 1,500 万，计划在 PC、PS5、iOS、Android 上线，并支持 12 种语言。
- 2026-11-21 官方 X 主页显示：英语约 18.9 万关注者，日语约 18.4 万，韩语约 2.6 万。
- 上述数字分别是发行方预约口径和社交兴趣指标，不代表活跃玩家数、独立人数或各语言玩家占比。
- Prydwen、Hideout、Everness 已覆盖部分国际攻略和数据库需求，单纯复制角色技能表的差异有限。

### 2.2 语言范围

| 语言 | 第一版范围 | 决策依据 |
| --- | --- | --- |
| 英语 `en` | 全部首版功能与已发布核心内容；默认入口 | 国际通用语言，有明确社区与检索需求 |
| 日语 `ja` | 首版界面、核心入门、优先案件与探索攻略、材料规划工具 | 官方社区兴趣信号强；与英语同步设计 |
| 韩语 `ko` | 保留扩展能力，首版不发布空栏目 | 有受众基础，待前两种语言维护稳定后评估 |
| 繁体及简体中文 | 后续可选 | 服务国际服华语玩家，不作为首版运营重心 |
| 其他官方语言 | 上线后按实际需求评估 | 暂无可靠的游戏语言受众拆分数据 |

日语采用“核心内容优先”，不承诺所有长尾页面同步翻译。机器翻译只作为草稿，关键术语、步骤、技能条件与剧透层级须校对后发布。无法完成校对时，先发布英语版本。

语言切换应指向同一内容的对应译文；缺少译文时，明确提示并提供英语原文入口，不跳到不相关页面。只有已发布语言出现在该篇内容的 `hreflang` 中。

### 2.3 内容与运营重点

- 角色与战斗玩家：提供清晰的培养顺序、配队用途和可替代方案，避免缺少实测依据的确定性排名。
- 探索与收集玩家：突出前置条件、楼层或区域、到达方式、完成状态确认。
- 剧情与推理玩家：突出分级提示与剧透控制，标题、缩略图和搜索摘要也避免泄露结局。
- 推广素材以能解决一个问题的攻略或工具为单位；选择符合社区规则的渠道后再制定发布安排。

## 3. 第一版范围

### 必须交付

6. 新手准备、战斗基础和资源规划内容。
7. 每篇内容的适用版本、来源、核验状态、更新时间与纠错入口。

### 后续建设

- 完整互动地图、地图切片与大规模点位采集。

## 4. 页面与导航

主导航：**Cases / Exploration / Characters / Tools / Guides**，另设搜索与语言切换。

```text
/{locale}/
  cases/
    {case-slug}/
  exploration/
    {guide-slug}/
  characters/
    {character-slug}/
  tools/
    material-planner/
    exploration-checklist/
  guides/
    launch-preparation/
    beginner-guide/
    combat-basics/
    resource-priorities/
  updates/
  about/
  editorial-policy/
  privacy/
```

- `locale` 首版取 `en` 或 `ja`。内容之间通过稳定 ID 关联，不依赖译文标题。
- 根路径 `/` 固定跳转 `/en/`；不按照 IP 强制选择语言。记住用户主动选择的语言。
- 英日译文优先共享稳定的 ASCII slug；页面标题、正文、关键词和术语按对应官方语言书写。
- 未完成的内容保留在内容仓库草稿中，不生成公开页面，也不进入搜索索引和 sitemap。
- URL 不包含剧透答案。分页、筛选与搜索状态不产生大量可索引的重复页面。

首页首先提供搜索、案件提示入口、探索入口和材料规划器；之后展示已核验攻略与近期更新。公测前明确标注准备阶段，公测后突出正式服核验结果。

## 5. 三个特色功能

### 5.1 案件分级提示

每篇案件攻略包含：案件名称、适用版本、前置条件、当前阶段选择，以及按阶段组织的四层信息。

| 层级 | 内容 | 默认状态 |
| --- | --- | --- |
| Brief | 已公开的任务背景、适用范围与前置条件 | 显示，避免关键剧透 |
| Hint | 下一步该观察或思考的方向 | 用户主动展开 |
| Evidence | 线索位置、交互对象、证据之间的关系 | 用户主动展开，标注剧透 |
| Solution | 完整操作、推理过程和结果 | 独立确认后展开 |

交互要求：

- 不因用户滚动或切换阶段而自动展开更深层答案。
- 记录展开状态时，以内容 ID、阶段 ID、内容修订版本区分，避免修订后错误沿用状态。
- 支持“重新隐藏所有答案”。隐藏区内的交互元素不可被键盘意外聚焦。
- 内站搜索、预览卡片、分享摘要和搜索索引只使用安全摘要，不收录 Evidence / Solution 正文。
- 分级提示保护正常浏览体验，不保证隐藏内容对网页源码、外部爬虫或第三方摘要不可见。

### 5.2 探索攻略与清单

每篇页面按“目标 → 前置条件 → 出发位置 → 路线与步骤 → 完成确认 → 常见卡点”编写。

- 有截图时标注方向、楼层、关键交互对象，截图同时提供文字说明。
- 未经验证的地点不编造坐标，使用已核实的区域名与地标描述。
- 清单项使用稳定 ID；只提供已有核验资料的条目，不提前声称覆盖全部收集内容。
- 勾选进度保存在本机浏览器，提供导出、校验后导入和确认后清空功能；明确本地保存范围。
- 正式服数据修订时保留可匹配的旧进度，新条目默认未完成。

### 5.3 养成材料规划器

首版计算材料缺口，不预先实现缺乏数据支持的体力效率、掉落概率或最佳刷取路线。

输入：角色、当前阶段、目标阶段、可独立选择的培养项目，以及已有材料数量。具体等级与突破系统按照核验后的游戏机制建模。

输出：总需求、已有数量、材料缺口、已核实的获取方式与材料清单。

计算规则：`缺口 = max(目标阶段累计需求 - 当前阶段累计需求 - 已有数量, 0)`。各培养项目分别计算后按材料 ID 合并；已有材料只在合并后扣除一次。

首版一次规划一个角色，避免多个角色错误重复使用同一份库存。没有确认的掉落和兑换数据不参与推算；缺少目标区间材料数据时显示“不支持该目标，资料待核验”，不按零需求处理。

所有结果标注数据版本。仅当至少一名角色的一个完整可选培养区间有可靠数据并通过验算后，规划器才对该区间开放。

## 6. 内容与数据管理

### 6.1 数据来源优先级

1. 官方国际服公告、商店页、游戏内文本与正式服实测。
2. 可确认版本与来源的公开测试资料，明确标注测试版本。
3. 获授权的玩家记录、截图和测评，保留署名与来源。
4. 其他攻略站仅作竞品研究、问题发现与交叉核对；不默认具有复制其数据、截图或文字的授权。

正式服与测试服差异单独记录。国际服资料与其他服务器存在差异时，不混用机制、数值和活动时间。

### 6.2 最小内容字段

| 字段 | 用途 |
| --- | --- |
| `id` / `slug` / `locale` | 跨语言关联、稳定地址 |
| `title` / `safeSummary` | 本地化标题与安全摘要 |
| `status` | `draft`、`reviewed`、`published`、`needs-review` |
| `gameVersion` / `server` | 对应版本与服务器 |
| `verification` | `official`、`live-tested`、`beta-tested`、`unverified` |
| `sources` | 来源地址或实测记录、查阅日期、素材使用依据 |
| `publishedAt` / `updatedAt` | 发布时间、最后实质更新 |
| `reviewedAt` / `translationRevision` | 核验时间、译文对应原文修订 |
| `relatedIds` | 关联案件、角色、材料、探索条目 |

内容状态与数据置信度分开管理。标为 `unverified` 的具体攻略和数值不公开；只有待核验状态明确展示、且不会造成误导的版本说明可以发布。

### 6.3 发布流程

```text
资料收集 → 来源记录 → 英语草稿 → 事实核验 → 英语发布
                                ↓
                     日语翻译 → 术语及步骤校对 → 日语发布
```

- 英语正文实质变更时，将相应日语译文标为待复核，不自动刷新其更新时间。
- 材料数值与计算逻辑分别审阅，保留人工验算样例。
- 更新日志记录影响玩家决策的变化，不把格式调整当作内容更新。
- 同一官方术语维护英日对照表；不自行把其他游戏同名机制套用到本游戏。

## 7. 技术与部署

### 7.1 第一版技术组合

| 层 | 选择 | 目的 |
| --- | --- | --- |
| 页面 | Astro + TypeScript，静态输出 | 内容直接生成 HTML，便于访问和检索 |
| 内容 | Astro Content Collections + Markdown/MDX | 校验元数据、关联与草稿状态 |
| 数据 | 经过 schema 校验的 JSON | 角色、材料、案件结构与语言映射 |
| 交互 | 小型客户端组件；具体组件库在实现时选择 | 仅为筛选、提示、计算等加载必要代码 |
| 搜索 | Pagefind，按语言生成索引 | 首版无需服务端搜索 |
| 本地状态 | 浏览器存储 + 版本化导入导出 | 保存清单和工具输入 |
| 发布 | GitHub + Cloudflare Pages | 自动构建、预览与生产部署 |

静态输出不需要为了部署而增加 SSR 适配器或数据库。R2、Pages Functions、D1 留待明确需求出现后增加。

构建时校验引用 ID、译文映射、版本、必要来源与数值区间。搜索索引在 Astro 输出后生成，只收录已发布内容和允许检索的安全片段。

### 7.3 Cloudflare Pages 配置基线

| 配置 | 值 |
| --- | --- |
| 连接方式 | GitHub 仓库集成 |
| 生产分支 | `main` |
| 构建命令 | `npm run build`，其中包含静态站点与搜索索引构建 |
| 输出目录 | `dist` |
| Node.js | 实施时选择依赖支持的 LTS 版本，并在项目与 Pages 中固定 |
| 域名 | `silverpalaceguide.com` 已注册；在部署阶段绑定 |
| 主机名规范 | 主域为规范地址，`www` 重定向到主域 |
| 预览 | PR / 分支预览；设置不被搜索引擎收录 |
| 统计 | Cloudflare Web Analytics；搜索表现通过 Search Console 验证 |

上线前验证 HTTPS、404、重定向、缓存头、canonical、sitemap 和语言对应关系。确保生产索引信号不会被预览环境的 `noindex` 配置污染。

按 2026-11-21 查阅的官方限制，Pages 免费计划每月 500 次构建、每站 20,000 个文件，单文件上限 25 MiB。多语言页面、图片变体和搜索索引共同计入文件数；实施与扩大规模时再次核对。

### 7.4 域名决策

已确定域名：`silverpalaceguide.com`，用户已完成注册。

显示品牌为 Silver Palace Guide，页脚使用非官方玩家站声明。站点规范地址使用该域名，DNS 和 Pages 自定义域名绑定在部署阶段完成。

## 9. 上线验收

### 内容与语言

- 所有公开攻略均有来源、适用服务器、数据版本、核验状态和实质更新时间。
- 不存在草稿、空占位、伪造坐标、未确认材料数值或把测试服资料标成正式服的页面。
- 英语无明显语法问题；日语核心内容完成术语、操作步骤与剧透校对。
- 链接、语言切换、图片文字说明及纠错入口可用。

### 功能

- 案件深层答案默认隐藏，阶段切换不自动泄露；安全摘要与搜索结果不含解答。
- 清单刷新后保留，导入能拒绝错误格式，清空前确认。
- 材料计算覆盖当前等于目标、库存充足、项目合并、非法输入、缺失区间数据等边界；与独立人工验算一致。
- 工具与清单在不登录的情况下可使用，存储被浏览器禁用时有清晰提示。

### 访问与检索

- 从首页到任一特色功能最多两次导航，窄屏无横向溢出。
- 核心交互可用键盘操作，焦点清晰，剧透状态可被辅助技术理解。
- 搜索支持英日内容隔离；角色与案件名称按对应官方语言可查找。
- 正式域名、HTTPS、404、重定向、canonical、hreflang、sitemap 配置正确。
- 代表性页面 Lighthouse 移动端性能目标为 90 分以上，记录设备模拟与网络条件；不把实验室分数当作真实用户 Core Web Vitals。
- Pages 预览和构建草稿不会进入生产搜索索引，能回退至保留的已知正常部署。

## 10. 指标、维护与成本边界

首月先建立基线，不预估缺少依据的日流量、收入或语言玩家份额。

- 搜索：按页面和语言观察展示、点击、查询问题及索引覆盖。
- 使用：观察案件提示、探索页面、工具的访问与回访；若需精确交互事件，另行选定采集方案和隐私说明。
- 内容：记录核验积压、纠错、英日翻译延迟和实际维护时间。
- 基础设施：关注构建次数、文件数和静态资源大小。

域名注册续费、日语审校、资料采集与截图是需要单独计入的成本。Pages 从免费计划起步；R2 和动态后端在引入时再核算，不预先假定零成本。

韩语及其他语言的扩展，应同时满足：已有实际需求信号、具备校对能力、核心英日内容更新没有明显积压。

## 11. 关键依赖与处理方式

| 依赖 | 处理方式 |
| --- | --- |
| 域名已注册，待部署绑定 | 开发使用本地预览；部署时配置 Pages 自定义域名、DNS 与 HTTPS |
| 正式服资料尚未实测 | 分离准备信息、测试资料和正式服结论，逐页解锁发布 |
| 案件或材料数据不完整 | 缩小支持范围，明确未覆盖部分，不把缺失值当作零 |
| 日语校对能力不足 | 保留草稿，减少首批日语数量，优先关键路径 |
| 第三方素材使用依据不明 | 采用自制素材、官方允许使用的素材或取得授权后使用 |
| 公测后更新量超过产能 | 优先修复影响操作和计算的错误，再扩充内容及语言 |
